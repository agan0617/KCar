# 賽道設計守則

KCar 的賽道目標是「玩起來像主機級卡丁車遊戲」：每一圈都有記得住的段落、有選擇、有節奏，不是一條同寬的管子。
格式見 [TRACK_V2.md](TRACK_V2.md)。這份寫「怎麼設計」。

## 物理數字（設計彎道與跳台用）

| 項目 | 數值 |
|---|---|
| 極速 | 40 m/s（儀表顯示約 250 km/h）；小噴、加速帶後可到 50～53 m/s |
| 不甩尾能過的彎 | 極速下轉速約 0.76 rad/s → 半徑約 50 m 以上全速過；更急要減速或甩尾 |
| 甩尾 | 路線轉速 0.35～1.25 rad/s（外拉～內切），點煞再多 1.1；35 m/s 時最急約半徑 25 m |
| 髮夾彎 | 半徑 18～25 m，要點煞＋甩尾 |
| 重力 | 30 m/s²；跳台飛行距離 ≈ v²·sin(2θ)/g（再加落差的修正）；`check_layout2.py` 會算最低需要速度 |
| 車寬 | 碰撞半徑 0.85 m；四台車並排要半寬 ≥ 6 |

## 原則

1. **節奏**：快慢交替。長直線不超過 250 m（要長就放加速帶、跳台、彎度很緩的高速彎讓它不無聊）。
2. **彎道多樣**：每條至少有 ① 全速可過的高速掃彎 ② 需要長甩的 120°+ 大彎 ③ 一個急彎或髮夾 ④ 左右連續的 S 彎；傾斜彎（`bank`）放在高速彎讓人敢全速壓過去。
3. **高低差**：一定要有上下坡與視野變化（坡頂看不到下坡、俯瞰全場的段落）。坡度 ≤ 18%。
4. **選擇**：至少一條捷徑——風險換時間（土路減速要靠小噴／氮氣才划算、窄、旁邊有熔岩或懸崖），或兩條路線各有優缺點。捷徑省 5～15% 的距離。
5. **地標**：每條有 2～3 個一看就記得的地方（大跳台、穿過鳥居隧道、橋下鑽過去再從橋上回來的 8 字交叉、海邊的碼頭…），放在彎道出口或坡頂，讓人「看得到下一段要去哪」。
6. **路寬變化**：起跑直線寬（半寬 9～10）；技術段窄（5.5～7）；不同寬度讓同一個彎有內外線選擇。
7. **護牆不要處處都有**：開放路肩讓失誤有代價（開進草地、沙地減速），危險邊（懸崖、熔岩）用 rail；城市賽道才幾乎全牆。
8. **加速帶**放在要用技術才吃得到的位置（彎心內側、跳台前、捷徑出口），一圈 2～4 個。
9. **一圈長度**：1.5～2.2 km，約 40～55 秒一圈，三圈約 2.5 分鐘。
10. **起終點**：起跑直線至少 150 m、平的、寬的；起跑後第一個彎不要太急（四台車擠在一起）。

## 驗證流程（每次改 layout 都跑）

```
python tools/check_layout2.py <id>                      # 長度、彎道半徑、坡度、交叉高差、跳台需要的速度、俯視圖 tmp_layout/<id>_v2.png
powershell -NoProfile -ExecutionPolicy Bypass -File tools\build_assets.ps1 -V2 -NoKart -Track <id>
node tools/sim.mjs tt <id>                               # 電腦自動駕駛：甩尾＋完美小噴 vs 不甩尾的圈速、撞牆次數
node tools/sim.mjs race <id> 6                           # 對 3 台電腦的名次分布
```

驗收標準：
- `check_layout2.py` 沒有錯誤
- 完美自動駕駛三圈都跑完、沒有掉落重生、撞牆少（一圈 ≤ 3 次）
- 「甩尾＋完美小噴」比「不甩尾」快 8% 以上（技術有回報）；難度越高差越多
- 渲預覽圖自己看（Blender 背景渲染，參考 `tmp_layout/render_preview.py`）：俯視全圖＋每個地標一張低角度近景
